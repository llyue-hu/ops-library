# 操作库（可复用操作手册）

给以后的各种项目复用。**只放通用做法**，项目专属规则（某个项目的语料/业务规范）不放这里。

本库来源：2026-10 考研英语真题批量整理项目。凡是「换个项目、把路径参数换掉还能原样跑通」的，才收进来。

本仓只放方法与工具，**不含任何语料/受版权保护的内容**；示例数据是生成的占位文本。

## 快速开始

```bash
python 04-下载加速与镜像/fetch_cache.py --selftest
python 09-批量产物结构验收/docset_qa.py --selftest
python 09-批量产物结构验收/docset_qa.py --spec 09-批量产物结构验收/spec.example.json
```

第三条跑的是内置夹具 `2099_示例_英语一`（全占位文本），输出 `1/1 个单元通过` 即表示环境正常。CI 在 Ubuntu / Windows × Python 3.10 / 3.12 上跑同样三条命令。

## 条目模板

每条固定五段，缺一段就不算写完：

1. **触发信号**：报错原文 / 现象关键词。未来靠症状检索，不靠项目名。
2. **30 秒判断**：先看什么，决定走哪条路。
3. **做法**：可复制的命令、脚本或提示词。
4. **验证**：怎么证明真的成了（读盘、重跑探针、比对哈希），而不是听谁说成了。
5. **坑与不适用**：什么情况下别用。

## 通用原则

1. **不信口头验收**：别人（包括 AI）说“已完成”，自己读盘复核。
2. **一个写者**：同一条输出路径同时只有一个执行者；换人先停旧的。
3. **中间产物落盘**：每一步解析结果存成 JSON/文本，换执行者时不用从头再来。
4. **配置外置**：脚本里不写死项目路径，路径、文件清单、期望数量都进 spec。
5. **同一件事做第二遍就沉淀**：第二次手动改同样的东西，就该写成脚本放进来。
6. **过期即删**：条目半年没被引用、或工具已升级，宁可删掉也不留错误指引。

## 维护

- 每个脚本：`python xxx.py --help` 必须能跑；带 `--selftest` 的，换机器先跑自测。
- 条目改动时同步改本页的症状速查表。
- 路径占位统一写 `<OUT>`、`<SPEC>`，不写某台机器的绝对路径。
